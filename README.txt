agenda-v25-widget: виджет «Урок сейчас» на рабочий стол

ВАЖНО: ставь ПОСЛЕ v24 (agenda-v24-schedule.zip). Виджет открывает вкладку «Расписание» и использует LessonClock из v24;
MainActivity.kt в этом архиве уже содержит правку v24 плюс одну строку v25.

ПОРЯДОК
1. git switch -c feature/widget
2. Распаковать zip поверх проекта (перезапишутся AndroidManifest.xml, MainActivity.kt, PortalExtrasStore.kt, остальное новое).
3. ./gradlew test (всего должно быть 38 тестов: 31 от v24 и 7 новых), затем Build -> Run.
4. На телефоне: долгое нажатие на рабочем столе -> Виджеты -> WatchYourGrade -> «Урок сейчас».
5. Всё ок: git add -A && git commit -m "Виджет: урок/перемена" && git switch main && git merge feature/widget

КАК ЭТО РАБОТАЕТ
- Обратный отсчёт рисует Chronometer (режим «обратный отсчёт», API 24+). Он тикает сам: без обновлений виджета, без расхода батареи.
- Виджет перерисовывается только на границах: конец урока, конец перемены, полночь. Время считает LessonClock.nextBoundary().
  На эту границу (+1,5 с запаса) ставится будильник AlarmManager.setAndAllowWhileIdle, тип RTC (без WAKEUP: телефон ради виджета не будим).
- Страховка: updatePeriodMillis = 30 минут. Плюс перерисовка при смене времени, часового пояса и даты, после обновления данных
  и после выхода из аккаунта.
- Данные берутся у ребёнка, выбранного в приложении (ChildStore.profileKey()).
- Цвет отсчёта: синий на уроке, зелёный на перемене и до первого урока.

КОМПРОМИСС (честно)
Точные будильники на Android 12+ требуют разрешения SCHEDULE_EXACT_ALARM, а в манифесте у тебя только INTERNET. Поэтому будильник
неточный: на границе урока виджет может опоздать на несколько секунд, а при спящем телефоне поправится в момент пробуждения.
За это время Chronometer успевает показать «-00:03» вместо перехода на перемену. Если это будет раздражать, следующим шагом можно
добавить разрешение и точные будильники, но это изменение политики и страница в Play Console.

ОТДЕЛЬНАЯ ПРАВКА: ОБЛАЧНАЯ КОПИЯ (allowBackup)
Находка при чтении кода. backup_rules.xml и data_extraction_rules.xml исключают из облачной копии только файлы первого ребёнка:
extras.json, grades.db, snapshot.xml, goals.xml. У второго и следующих детей аккаунта файлы называются extras_<id>.json,
grades_<id>.db, snapshot_<id>.xml, goals_<id>.xml, и правила на них не распространяются (path в правилах точный, без масок).
То есть уроки, оценки и пропуски второго ребёнка могли уходить в Google-бэкап, а политика обещает обратное.
Самое надёжное исправление в одну строку: android:allowBackup="false". Пользователь ничего не теряет: логин и так исключён,
а тема восстанавливается за секунду. Если не хочешь это менять сейчас, верни в манифесте allowBackup="true", виджет от этого не зависит.
Проверить на телефоне это нельзя, вывод сделан по тексту правил.

ПРОВЕРЕНО
- WidgetPlanner собран настоящим kotlinc и прогнан вместе с тестами v24: 38 тестов, все зелёные.
- Тест «идём по дню»: от 07:00 до полуночи ровно 15 состояний (в том числе 6 перемен), каждое обновление меняет состояние, зацикливания нет.
- Тест «обновление всегда в будущем»: для каждой минуты суток время следующей перерисовки строго позже «сейчас» и не дальше суток.
- Мутации (намеренные поломки) ловятся: нет запаса после границы, перепутаны цвета перемены и урока. Мутация «запас 0» сначала не
  ловилась, тест усилен.
- XML разбирается, все ресурсы существуют, жёстких цветов нет, скобки сходятся, настоящих имён и номеров сессий в файлах нет.
НЕ ПРОВЕРЕНО
LessonWidgetProvider, RemoteViews, вёрстку и будильник я не компилировал и на экране не видел (нет Android SDK).
Больше всего риска: setChronometerCountDown в RemoteViews на некоторых лаунчерах и поведение будильника при экономии заряда
(у Xiaomi, Huawei и Samsung агрессивный режим может откладывать будильники дольше).
